# Corrupted! — код гри

Династична стратегія про корупцію: 7 епох, по 2 покоління в кожній. Код написано на TypeScript, інтерфейс буде на React (через Vite). Під ПК гра пакуватиметься Tauri або Electron, під iOS та Android — Capacitor.

Стан: **кроки 1–2 з 4** (ядро гри та дані епох). Гарний інтерфейс за макетами з канвасу — це крок 3. Поки що є тільки консоль розробника.

## Запуск

```bash
npm install
npm run dev        # консоль розробника: http://localhost:5173
npm test           # тести, разом із перевіркою на збіг із HTML-прототипом
npm run sim -- 500 # симулятор балансу: 500 кампаній для кожного стилю бота
npm run extract    # перегенерувати дані епох із прототипу
npm run build      # перевірка типів і збірка
```

## Структура

```
src/engine/            ядро гри: чистий TypeScript без інтерфейсу
  types.ts             типи стану гри та контенту
  rules.ts             усі числа балансу в одному місці
  game.ts              дії гравця та правила (рік, кабінет, сейф, ніч, родина, вибори, заповіт)
  content.ts           доступ до даних епох і рядків
  rng.ts               детермінований генератор випадковості (стан лежить у збереженні)
  text.ts              форматування чисел і шаблони тексту
src/data/
  strings.base.uk.json рядки Епохи I, з яких генеруються рядки інших епох
  eras/era1..7.json    згенеровані дані епох (не редагувати вручну)
src/sim/bot.ts         боти, що грають самі (для тестів і балансу)
src/ui/                консоль розробника (тимчасовий інтерфейс)
scripts/               extract-content.mjs (дані з прототипу), sim.ts (статистика)
prototype/             знімок HTML-прототипу, з якого взято логіку й дані
test/                  тести ядра й тест на збіг із прототипом
```

### Як влаштоване ядро

- **Стан гри — один простий об'єкт `GameState`.** Він цілком зберігається в JSON, тож збереження гри — це просто `JSON.stringify(state)`.
- **Кожна дія — чиста функція `(state, …) → новий state`.** Наприклад: `signForm`, `toOffice`, `setAppetite`, `signScheme`, `declineScheme`, `pickOption`, `adjustAlloc`, `allTo`, `togglePay`, `toggleKidPay`, `lockSafe`, `acceptOffer`, `sleep`, `campaignAct`, `electionNight`, `pickHeir`, `restart`.
- **Інтерфейс нічого не рахує сам.** Що показати, він питає в селекторів ядра: `docsFor`, `currentDoc`, `schemeDelta`, `enabledOptions`, `isFatal`, `raidOdds`, `unhidden`, `kidStashTarget`, `offersFor` тощо.
- **Випадковість детермінована.** Однакові `seed` і однакові рішення завжди дають ту саму гру. Через це можна відтворити баг за записом ходів.
- **Подвійне натискання (тап → прев'ю → тап) належить інтерфейсу.** Ядро дає лише дельту ефекту для прев'ю.

### Дані епох

`npm run extract` бере з прототипу дані кожної епохи і складає `src/data/eras/eraN.json`:
- посади, імена, походження, мрії, схеми, рішення, слова епохи (вибори, діалоги, діти, освіта), описи шкал;
- тему (кольори, «look» епохи, іконки) для кроку 3;
- рядки ядра. Рядки епох II–VII виходять із `strings.base.uk.json` через ті самі заміни, якими генератор прототипу адаптував тексти.

Шаблони рядків пишуться так: `{name}` — це підстановка, а `{пішов|пішла}` — форма за родом.

## Збіг із прототипом

Тест `test/parity.test.ts` запускає код прототипу (Епоха I) поруч із TypeScript-ядром:
- обидва отримують однакову випадковість і однакові рішення;
- після кожного кроку порівнюються шкали, гроші, спільники, діти, заголовки газети й нічний звіт.

Результат: **23 103 кроки збіглися повністю**. Це 450 перших життів трьома стилями гри.

### Свідомі відмінності від прототипу

1. **Гроші не йдуть у мінус.** У прототипі можна було вибрати варіант, на який грошей немає, і чисті ставали від'ємними. В ядрі є `enabledOptions`: варіант, на який не вистачає грошей, вимкнено. Якщо не вистачає на жоден, увімкнено всі, і платиш скільки маєш. За «чисті» варіанти (наприклад, пожертва на балу) можна платити лише чистими.
2. **Виправлено закінчення за родом.** У прототипі писалося «заснувла», «грюкнувла», «пішовла». Додано «програла вибори» для героїні.
3. **У питанні схеми було «6 000 кр..»** (дві крапки). Виправлено селектором `schemeText`.
4. **Перехід між епохами.** Прототип зупинявся на «тут почалася б епоха II». Ядро продовжує:
   - спадкоємець другого покоління відкриває наступну епоху;
   - чисті гроші, діти, брати й сестри переходять разом із ним;
   - спільники й посади беруться з нової епохи.
   - Якщо рід падає (провал покоління з тавром), кампанія починається з Епохи I. Після VII епохи кампанію завершено.
   - **Це припущення. Механіку переходу між епохами треба затвердити.**

## Що показує симулятор (`npm run sim`)

- **Випадкові боти** («careful», «average», «greedy») майже завжди гинуть у першій епосі. Найчастіше від бунту, викриття й зради.
- **«Розумний» бот** бачить прев'ю ефектів, як і гравець, і тримає шкали біля середини. Він проходить **усі 7 епох у 100% кампаній** і майже завжди йде у відставку. Тобто для уважного гравця гра зараз **надто легка**. Тут потрібне балансування: ризик, що росте з роками, частіші обшуки, ціна відставки.
- **Утримання дітей дороге для обережного гравця.** Розумний бот бере мало, і чистих не вистачає на 1–3 дітей. Тому діти масово зрікаються роду.

Усі ці числа зібрано в `src/engine/rules.ts`.
